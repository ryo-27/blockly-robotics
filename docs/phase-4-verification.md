# Phase 4 機体と指示の操作画面

2026年11月20日に参加者管理を外し、11月21日に指示作成後の機体選択・固定画面・統合管理パネルへ変更。
学習の進行・課題・気づきは参加者の手元のプリントで管理し、端末は機体の選択と指示の作成・送信・停止に使う。
参加者の登録・切替・トークン発行、個人別の保存一覧・学習履歴は画面に設けない。

React / Blocklyを使い、模擬機体で送信と完了表示、作成中の下書き復元を確認済み。
2026年11月21日に利用者から、画面を使った単機での実行確認完了の報告を受けた。Phase 4の実機確認を完了とする。
機体とのprotocolVersion=2は変更しない。複数機の実機確認はPhase 5で別に扱う。

## 起動

Node.js 22.12以上（またはViteが対応する新しいLTS）とnpmを使う。ルートから実行する。

```sh
npm ci --prefix apps/web
npm run build --prefix apps/web
```

ビルド後にロボット用APIを再起動する。個体設定・DB・ファームウェア設定はそのまま保持する。
別システムの8000番サーバーは停止しない。

```sh
cd apps/server
uv run --locked uvicorn app.main:app --host 0.0.0.0 --port 8000
```

MacのLANアドレスのルート（例：`http://192.168.179.45:8000/`）を開く。
APIと画面は同じオリジン。ビルド先は既定apps/web/dist、WORKSHOP_WEB_DISTで変更できる。
開発時は `ROBOT_API_URL=http://192.168.179.45:8000 npm run dev --prefix apps/web` で5173番から開く。
接続先のアドレスはMacの現在のLANアドレスへ置き換える。Vite previewはAPIをproxyしない。

## 画面と管理（2026年11月21日更新）

通常画面はヘッダー・ブランド表示・説明エリアを持たず、ブラウザの高さに固定する。
ブロック編集を全面に広げ、自動生成する指示一覧や送信前の要約は表示しない。
子どもがブロックを読んで動きを考え、実機で確かめる。下部の説明文とショートカット案内も表示しない。
送信・停止を下端、管理ボタンをツールバーへまとめ、ページ全体はスクロールさせない。
1280×720、768×1024、1024×768でページ寸法と送信・停止操作の収まりを確認した。

「管理」を開くと、機体の状態・接続設定・DB確認を中央に開く一つのモーダルで切り替えられる。
接続設定は運営者がstationTokenを入力する。参加者の登録は不要。
接続しなくてもブロックの作成はでき、送信には端末の接続設定が必要。

## 指示を作ってから機体を選ぶ

1. 送信先を決めずに「はじめる」へブロックをつなげる。
2. 自分でつなげたブロックを読んで、動きを予想する。自動生成の順番一覧は出さない。
3. 「ロボットを選んで送る」を押す。この時点で指示を固定し、機体選択ダイアログを開く。
4. 空いている機体を選ぶ。最初から機体を自動選択せず、この段階ではまだ送信しない。
5. 機体名付きの「○○へ送って動かす」を押して送信する。
6. 実際の車輪の動きと完了表示を確認する。必要なら「停止」を押す。動いているすべての機体へ停止を要求する。
   個別停止は管理パネルの機体の状態から行える。

作成中の下書きはworkspaceDraftとしてこのタブのsessionStorageへ保持する。
下書きは送信先に属さず、同じ指示を作成後に別機体へ送ることができる。
旧画面の下書きがある場合、初回だけ最後に編集していた機体の内容を引き継ぐ。
参加者・名前付き保存・課題達成・学習進捗は持たない。学習の記録はプリントを使う。

送信するASTと要求IDは下書きとは別に固定する。送信後に下書きを編集しても受付済み実行へ影響しない。
結果が不明な送信は管理パネルに表示し、同じ機体・AST・requestIdで結果を再確認する。
ページ再読込や機体選択だけでは自動走行しない。未確認要求がある機体へ別内容を重ねて送らない。

## DB確認（開発用）

管理パネルの「DB確認」から、SQLiteのファイル名、テーブル一覧と件数、列の型・主キー、
最新の行を確認できる。25行ずつページを切り替え、「表示」で行の内容をJSONとして開く。
長いテキストは各値の先頭4000文字まで。認証情報のtoken_hashは表示しない。

APIはstationTokenが必要。DBをmode=ro・query_onlyで開き、許可したテーブルだけを閲覧する。
SQL入力・更新・削除機能は持たない。DBがない場合はファイルを新規作成せず、その旨を表示する。
閲覧は短い時間で打ち切り、制御通信を長時間妨げないようにする。
DB閲覧はrobots・executions・robot_events・sqlite_sequenceのみ。旧参加者・保存・予約表はバックアップ後に廃止する。

COMPLETEDは機体が命令を処理した報告で、実際の距離や角度を検出した結果ではない。
通信できない場合はモーター用電源スイッチで停止する。

## 自動検証

```sh
npm test --prefix apps/web
npm run build --prefix apps/web
```

BlocklyとASTの往復、REPEATの展開・上限、送信先選択前の指示固定と機体への割り当て、通信エラー後の同一要求再送、
参加者・保存・予約APIを使わない送信、LAN内HTTPで利用できるUUIDを検証する。
Blockly mediaはローカルへコピーして配信し、CDNへ依存しない。

管理モーダルはEscape・閉じるボタン・背景クリックで閉じられる。開いた時は閉じるボタンへフォーカスし、閉じると元の操作へ戻す。

## 縮尺と中央表示（2026年11月21日）

初期倍率は約79%（約66%からプラス1回分）。拡大・縮小後に中央ボタンを押しても倍率は変えない。
管理モーダルから指定の3説明文を削除。画面にページスクロールが発生しないことを確認する。

ブロックの接続・空の繰り返し等のサポート文と開始ブロックのツールチップは表示しない。
不正な構造の送信制限は維持する。Blocklyのスクロールバー領域は端末共通で12px（ハンドル7px）とする。

## クエスト・ifの追加確認（2026年11月21日）

- 応用ブロックのIFを接続し、前進可否とマスの種類を切り替える。
- IFを含む場合、送信先機体を選んでもクエスト未選択なら送信ボタンは無効。
- クエスト選択後に模擬機体へ送信し、開始前には正誤を表示せず、完了後にマップ上の判定を表示する。
- 岩・境界・途中の通過マス、後退、IF/REPEATの再評価、停止時の判定非表示はサーバー試験で確認。
- 8つのアプリ用マップは教材を基にし、ゴール位置だけで判定する。紙の経由・向き・最小化課題はアプリでは判定しない。
- 2026年11月21日に利用者から単機での実行確認完了の報告を受けた。項目別の測定値は未記録。
- マップ上の位置・向きは実機センサーの値ではない。
