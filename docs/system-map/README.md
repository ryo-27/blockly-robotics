# Blockly Robotics システムマップ

サーバー・ESP32・設定ファイル・DBの役割を、図と実装ソースでたどる開発用ページ。
ASJの `packages/backend_map` の視点別タブ、所属ごとの図、要素・接続の解説、
参照ファイルの表示を参考に、このリポジトリのPhase 1を説明する。

## 開く

`index.html` をブラウザで開く。外部ライブラリ・CDN・API接続は不要。
通常のファイル表示でも使えるよう、JSONをfetchせず、生成済みのJavaScriptを読み込む。

HTTPで閲覧する場合は、リポジトリルートで次を実行する。

```sh
python3 -m http.server 8010 --bind 127.0.0.1 --directory docs/system-map
```

ブラウザで `http://127.0.0.1:8010/` を開く。
APIサーバーの8000番ポートとは独立している。マップ自体は機体の稼働状態を取得しない。

## 読む順序

1. **全体構成**：端末、MacBook、ESP32、DB、停止出力の役割と実際の接続。
2. **起動と設定**：サーバー起動時に読むJSONと、ビルド時に取り込むESP32ヘッダーの違い。
3. **登録とHeartbeat**：認証、型検証、bootId・sessionId・sequence、応答検証。
4. **接続状態と復旧**：3秒の接続期限、再起動、Wi-Fi再接続、モーター停止の維持。
5. **ファイル索引**：ファイル名から説明とソースを探す。

ノードと接続線はクリックまたはEnter・Spaceで選択できる。
右の説明欄（狭い画面では図の下）に、番号付きの処理図、条件と結果、入力と出力、
処理の役割、設定と動作、参照コードを表示する。「処理」「設定」「コード」から該当箇所へ移動できる。
日本語の説明と関数名・設定キーのコード表記を分け、ソースではキーワード・文字列・コメントを色分けする。
配色はASJの青（サーバー）・緑（保存）・紫（ESP32）を使い、設定は中立色、未実装は破線で示す。
「実装ファイル」を開くと該当箇所、「ファイル全体を読む」で生成時の全文を読める。
図の下の手順を選ぶと、関連する要素を強調する。

検索は機能名、ファイル名、設定キー、説明を対象にする。`/`で検索欄へ移動できる。
図の背景をドラッグして移動し、拡大・縮小ボタンまたはCtrl/Cmd＋スクロールで倍率を変える。
タッチ端末では図をスクロールする。文字を小さくしすぎないため、狭い画面では横スクロールを使う。
「全体表示」は表示幅に合わせて倍率を調整する。タブごとに閲覧位置・倍率を保持する。

表示中の図・要素・接続・ファイルはURLのハッシュに残るため、直リンクと戻る・進むを使える。
例：`index.html#startup?node=firmware-config`。

## 説明とソースの更新

- `map.json`：概念の説明、入力・出力、設定の意味、ノード配置、接続、手順。
- `app.js`：図・選択・検索・ファイル索引・URL状態・説明欄。
- `style.css`：配色、配置、狭い画面での表示。
- `index.html`：閲覧ページの骨格。
- `data.js`：生成された説明と公開ソースのスナップショット。直接編集しない。
- `../../scripts/build_system_map.py`：参照パス・検索文字列・図の接続を検査し、data.jsを生成。

ソースの責務、設定、処理経路を変えたら `map.json` の該当箇所を直し、
リポジトリルートで再生成する。

```sh
python3 scripts/build_system_map.py
python3 scripts/build_system_map.py --check
node --check docs/system-map/app.js
```

`--check` はソースや説明と生成物の不一致、存在しない参照、無効な接続を検出する。
説明文の正しさを自動推定するものではないため、動作変更時は説明と図も見直す。

生成器は列挙した公開ファイルだけを読み込む。`config/local.json`、
`firmware/include/robot_config.h`、DB、ビルド成果物、個体トークン、Wi-Fiパスワードの
実際の値は収録しない。設定ファイルは雛形を参照する。
実装済みと未実装を区別し、将来機能へ実際の通信線を引かない。
